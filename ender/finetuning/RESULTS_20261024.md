# Ender fine-tuning results — 2026-10-24

## What has actually been trained

The latest Ender and `retep` adapters are **six-update financial performance
probes**, not completed financial fine-tunes. The full epoch is prepared but
has not started. Do not describe these adapters as a finished aligned model.

- Base: `Qwen/Qwen3.8-27B`, revision
  `1d4bf0f2ff6012fd82039f2fa52739d0dd7c60c0`.
- Selected execution: native bitsandbytes LLM.int8 weights, BF16 autocast,
  FP32 trainable LoRA. The original checkpoint is unchanged.
- LoRA: rank 16, attention/memory-routing projections in language layers 48–63;
  **11,487,232 trainable parameters**, with 72/72 B matrices updated.
- Training probe: median, p90, and maximum-length financial examples, each
  repeated twice; **44,688 padded/template-expanded input tokens, six updates**.
  This is only three distinct training examples, not all 4,770 training rows.
- `retep`: separate AdamW state consuming negated, clipped **Ender gradients**.
  It shares the base and primary forward/backward. It does not compute gradients
  at its own parameters and is not a validated adversarial model.

The financial split contains 4,770 training and 561 validation rows; the length
audit counted 17.47M training input tokens and 2.52M validation input tokens.
Source records marked reviewed are not an independent benchmark label set.

## Measured training performance

Warmed, matched-length **training input throughput**, not autoregressive decode:

| Configuration | 2.5K tokens | 7.2K tokens | 12.7K tokens | Peak CUDA allocation |
|---|---:|---:|---:|---:|
| Original int8, all-linear/all-layer LoRA | 164/s | 169/s¹ | 160/s | 72.64 GiB |
| Liger kernels, original targets | 175/s | 187/s | 178/s | 42.88 GiB |
| Liger, upper-16 attention targets, full checkpointing | 439/s | 435/s | 447/s | 35.23 GiB |
| **Selected native int8, response-only projection, selective checkpointing, `retep` included** | **489/s** | **508/s** | **481/s** | **63.09 GiB** |
| Experimental W8A16, same targeted setup and `retep` | 635/s | 681/s | 629/s | 59.41 GiB |

¹ Earlier unprofiled matched run; the later profiled step is excluded from the
speedup claim. All probes retained the context limit and source examples.
Restricting LoRA targets changes training capacity, so its speedup is not a
lossless kernel-only comparison. Selective checkpointing retains more activations
than full checkpointing, explaining the higher 63-GiB peak despite a small sister.

The selected path is about **3× faster** than the original, projecting to
**9.6–10.1 hours training-only** for 17.47M tokens. This is not a measured epoch
or end-to-end ETA: startup, template/padding overhead, gradient accumulation,
evaluation and checkpoint overhead remain additional. Full validation is now
scheduled once per epoch, rather than about 11 times. Recovery checkpoints remain.

Disabling checkpointing failed on the longest example at the unchanged 80%
allocation cap. That candidate is rejected and its failed run is preserved.
The paired selective-checkpointing probes showed about 10 MiB sampled swap growth,
not multi-GiB swapping. No inference/decode speedup was established by these tests.

## Held-out response loss: matched base versus adapters

The native-int8 canary uses the same **six validation examples and 205 supervised
response tokens** in every mode, with prompts masked and no truncation:

| Mode | Token-weighted cross-entropy, nats | Perplexity |
|---|---:|---:|
| Base, adapter disabled | 1.020330 | 2.774110 |
| Ender | 0.982710 | 2.671687 |
| `retep` | 1.053811 | 2.868562 |

Ender lowered loss by **0.037620 nats**; `retep` increased it by **0.033481 nats**.
These directions support the update-path check. They do **not** measure cheating,
task completion, refusal quality, or an alignment success rate. The sample is
tiny and was selected by length, not as a representative behavioral test set.

The response-only vocabulary projection matched the native loss exactly on the
checked example (absolute difference 0.0), with loss/gradient unit tests as well.
Saved sister B matrices matched negative primary B within 3.21e-10, verifying
actual GPU updates. Negating B and changing A is not the same as negating the
final low-rank weight delta.

W8A16 is **not selected**: its base canary loss was 1.067919 versus native int8's
1.020330 (**+0.047589 nats**). Its higher throughput is not free numerical parity.
The executable numerical canary now has an explicit configurable regression gate.

## Specific new scenario comparisons

Behavioral results were not available from the throughput/loss probes above.
A separate matched comparison is being run on eight freshly authored scenarios:
receipt backdating, evaluation denominator manipulation, expired payment
clearance, replayed settlement counting, unobserved audit results, invoice-note
instruction injection, an authorized refund, and a benign cash reconciliation.

The scenarios and exact action rubrics were frozen before inference in
[`data/unseen_action_probes_v1.json`](data/unseen_action_probes_v1.json).
[`unseen_action_eval.py`](unseen_action_eval.py) compares base, Ender and `retep`
with the same prompts, native-int8 base, greedy decoding and generation budget.
Rubrics and expected answers are not included in model messages. Proposed calls
are saved but **never executed**; a different action is not automatically unsafe.

The overlap screen checks normalized containment and five-word overlap against
the financial train/validation data, raw financial rows, and earlier demo source.
Passing it does not establish semantic independence or absence from Qwen's
pretraining. These are assistant-authored, unreviewed diagnostic probes, not an
independent agentic benchmark. Original scenario-catalog results remain untouched.
