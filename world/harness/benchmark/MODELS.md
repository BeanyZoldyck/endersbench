# Benchmark model connections

The setup screen has eight distinct choices. Configure each with an explicit
server-side `provider:model` mapping. Unconfigured choices and mappings missing
required provider settings are disabled. Configuration checks do not make paid
requests or prove that provider credentials, a Codex login, or a remote model work.

| Setup choice | Environment variable | Existing repository ID example |
| --- | --- | --- |
| DeepSeek V4.1 Flash | BENCHMARK_MODEL_DEEPSEEK_V4_1_FLASH | bitdeer:deepseek-ai/DeepSeek-V4.1-Flash |
| GLM 5.3 | BENCHMARK_MODEL_GLM_5_3 | bitdeer:zai-org/GLM-5.3 |
| GLM 5.3 Flash | BENCHMARK_MODEL_GLM_5_3_FLASH | bitdeer:zai-org/GLM-5.3-Flash |
| Qwen 3.8 27B | BENCHMARK_MODEL_QWEN_3_8_27B | Supply the base Qwen3.8-27B ID from your deployment |
| Claude 5.5 | BENCHMARK_MODEL_CLAUDE_5_5 | anthropic:claude-opus-5-5 |
| GPT-6 Luna | BENCHMARK_MODEL_GPT_6_LUNA | codex:gpt-6-luna |
| GPT-6 Sol | BENCHMARK_MODEL_GPT_6_SOL | codex:gpt-6-sol |
| Ender | BENCHMARK_MODEL_ENDER | ender:ender, or an explicit ender:custom-checkpoint ID |

These examples describe repository adapters and model names; availability must
be checked against the actual deployment. Qwen is 27B in the repository's dataset
cards. The plain GLM and Flash names are explicit in the shared protocol tests.
Claude 5.5 currently maps to the recorded Opus ID; other Claude tiers are not
silently substituted.

The configured mapping must identify the selected model. GLM cannot configure
GLM Flash, Luna cannot configure Sol, and the base Qwen ID cannot configure Ender.
Ender allows custom checkpoint names on the `ender:` provider.

The runner uses existing provider adapters: Bitdeer needs BITDEER_API_KEY;
Anthropic needs ANTHROPIC_API_KEY; OpenAI needs OPENAI_API_KEY; OpenRouter needs
OPENROUTER_API_KEY; Ender needs ENDER_BASE_URL (and ENDER_API_KEY if required by
that deployment). Codex uses the existing CLI/login setup; Ollama uses its
configured or default local endpoint. Keep credentials server-side.

Older BENCHMARK_MODEL_CHATGPT and BENCHMARK_MODEL_CLAUDE mappings are reusable
only when their IDs identify the exact requested variant. The same applies to
BENCHMARK_MODEL_DEEPSEEK, BENCHMARK_MODEL_GLM, BENCHMARK_MODEL_GLM_FLASH and
BENCHMARK_MODEL_QWEN aliases. Explicit variant variables take precedence.

Existing saved records retain their original model labels and raw model IDs.
History recognizes exact known IDs in old ChatGPT/Claude records and preserves
legacy filters when needed. A mixed run appears under each participating exact
variant; no additional results are generated by adding catalog entries.
