# Lobby backend handoff

Outcome: POST /api/benchmarks accepts a strict mixed roster of 1–4 total slots. Counts are positive integers; model names must be known and unique; extra request/roster keys and unsupported or disabled scenarios are rejected. The legacy {model,scenario} request expands to four matching slots. New jobs and history rows persist resolved roster entries; legacy model/modelId fields identify the first entry, so clients should use roster for mixed attribution.

Changed backend files: types.ts, config.ts, service.ts, executor.ts, worker.ts, completion.ts, store.ts; added roster.ts, scenarios.ts, ledger.ts and focused regression tests. Existing recording/store/HTTP/lifecycle work copied into this checkout was preserved. The only edit outside benchmark/ is an authorized type-only tool-schema assertion in finance/desk.ts.

The Clearing uses the one actual map and charter prompt. Survivor names are stable and unique, and worker assignments are bound to persisted agent IDs. Requests must match agent ID, name, kind, and configured model. Completion verifies the selected roster size and its identities.

Ledger Street uses the mounted finance desk with one lend-clean-approve case per slot, house-rules prompt, and saved CRS snapshots. Selected counts become repeated case episodes. Each actual financeCase ID is bound to its selected slot, including when two roster entries map to the same provider model ID. Request routing checks agentId 0, the open case's pendingRequestId and model ID. The injected brain transport avoids the finance provider factory's .env fallback and never enables live CRS. Recordings include finance_case/step/verdict tables. Ledger reports contain scenario, caseId, variant, per-model case/pass counts and compliantCompletion, plus cases with slot and verdict evidence. This is a single-case lobby run, not the complete finance benchmark suite.

Validation run: strict TypeScript check of benchmark worker/server with ES2022, bundler resolution, Node types; benchmark:build; Vitest benchmark and finance/desk.test.ts (9 files, 39 tests). HTTP regression launches and restores a mixed roster. Tests cover count validation, identity spoofing, sizes 1–4, legacy launches, disabled scenarios, mixed history, desk adapter submission with an injected brain, and Ledger journal conversion validated by parseFinanceRecording. Ledger replay endpoint emits plain FinanceRecording JSON with lineup:true; Clearing keeps gzip delta replay.

Limitations: no provider calls, secret/.env reads, real benchmark runs, or local SpacetimeDB publication were performed by this worker. The desk adapter test uses a simulated connection; database scheduling, browser live routing and browser live routing and saved Ledger replay presentation need root integration review. The catalog contains only clearing-charter and ledger; no second Clearing map was invented.
